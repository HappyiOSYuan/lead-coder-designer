# 最坏数据 UI 压测

改编自 `break-ui` 思路。演示数据和测试账号的数据往往「太好看」：名字一行放得下、金额不过万、可选字段都有值。在改写或验收前，用真实但极端的数据把列表、详情、表单压测一遍，提前暴露截断、溢出、挤压和空值错显。

## 什么时候用

- 列表 / 详情 / 表单的新页面或大改版，在验收前
- 旧页面重写（如跨框架迁移、重构）验收前
- 用户说「压测一下」「边界情况」「数据长了会不会乱」

## 硬规则

1. **数据要真实，或者取接口/库表的真实上限。** 无意义的 `"啊啊啊…"` 或 5000 字说明不了问题。每个值要么是真实用户会输入的，要么是后端字段上限；查不到上限就在报告里标「无上限」，再取一个长但可信的值。
2. **只换数据，不改组件。** 极端数据从数据适配/映射层注入，走真实渲染路径，不要为了展示效果去改 View 或约束。
3. **一组数据覆盖多种失败。** 列表前几行分别放不同坏法（第 1 行超长名、第 2 行缺字段、第 3 行单字名），贴近真实混合场景。
4. **默认只读，先报告再修。** 截断还是换行、缺字段隐藏还是占位，属于设计决定。先出报告并给建议，用户点名后再派编码角色修。
5. **注入的假数据绝不交付。** 不加 `#if DEBUG` 假数据开关；若需真机/模拟器实看，截完一张图后立刻还原，确认 `review_diff.py` 和 diff 里零残留。

## 流程

1. **列字段表（只读）**：读页面、Cell、Model/映射层，列出画面上显示的每个字段（来源、类型、上限、可空性），别漏掉导航栏标题、角标、状态标签、按钮上的动态文案、空态与分页条数。
2. **配最坏数据**：按下方清单选值，并**单独覆盖三种集合边界**：
   - **0 条**（空态、搜索无结果、全部可选字段为空）
   - **1 条**（单条记录、计数正好为 1）
   - **满页边界**（正好一页如 20 条、以及一页 +1 条，查「没有更多了」与重复拉取）
3. **找坏点**：
   - 默认由主控**读代码推断**（查约束、抗压缩优先级、行数限制、固定高度、空值清洗、数字格式）；
   - 必要时派编码角色临时注入数据，在窄屏与常用屏宽各截一张图后还原。
4. **出报告并停下**，等用户拍板要修哪些。

## 常见最坏数据清单

| 类别 | 极端值示例 | 容易坏在哪 |
|---|---|---|
| 人名 / 组织 | 超长人名（含间隔号）、单字名、长公司名、多级部门路径、空 / `null` / `"null"` / 首尾空格 | 单行溢出、挤掉右侧状态标签、首字头像异常、显示 `<null>` 或 `Optional(...)` |
| 编号 / 文件名 | 长无空格单号、带版本号的中文长文件名 `2026年Q3汇总(修订版)v12.xlsx`、大写扩展名 | 无换行点撑破容器；尾部截断吃掉扩展名（文件名应保留开头 + 扩展名） |
| 文本 / 状态 | 带换行的多行备注、500 字长文本、未知状态码、同页出现所有长度的状态标签、带 emoji | 换行被吞、行高翻倍、固定高度被切、`switch` 漏默认、截断半个字符 |
| 金额 / 数字 | `0` / `0.00`、千万级大额、负数、浮点 `0.1+0.2`、带逗号的字符串 `"1,234.00"`、动态变化 `99→100` | 精度丢失、合计溢出、除以 0、非等宽数字刷新跳动 |
| 列表 / 分页 | 0 条、1 条、满页 / 满页+1、某行高度是其他行的 10 倍、同名项 | 空态不居中、单卡片怪异、分页死循环、固定行高互相遮挡 |
| 时间 | `0` / `1970-01-01`、秒级 vs 毫秒级、跨年、跨天 `23:59–00:00`、开始晚于结束 | 空时间戳当真日期显示、差 1000 倍、负时长 |
| 图片 / 附件 | URL 404 / 慢加载、超宽 4000×200 / 超长 200×4000、多图超限、0 附件 | 缺占位图、拉伸变形、0 附件还留空标题块 |
| 状态 / 权限 | 加载中、接口失败、部分字段有值、无权限、本人出现在操作列表中 | 骨架与真实布局错位、直接暴露原始错误、行间对不齐、误对自己开放操作 |

## 截断、换行还是限行（按字段单独决定）

- **换行**：必须看全才能识别的主信息（姓名、详情标题、事由）；超过 3–4 行说明列宽不够。
- **尾部截断**：开头就有区分度的次要信息（部门、备注预览），需有出口能看全文。
- **保留开头 + 扩展名 / 中间截断**：结尾才区分身份的值（文件名保留开头 + 扩展名；长单号/路径用中间截断）。
- **限行**（如 2 行）：卡片预览，保住卡片节奏。
- **永不截断**：金额、日期、数量和用于对比的数值，必须给够空间并开启等宽数字。

## 报告格式

1. **坏了什么**（按严重程度排序）：表头 `字段 | 极端值 | 现象 | 原因 | 建议修法 | 推断/实看`
2. **需要用户决定的**：截断还是换行、缺字段是否隐藏等，每条给一个推荐项
3. **扛住了的**：一句带过哪些字段没问题

报告只输出在回复里或放工程目录外，不写进工程目录。
