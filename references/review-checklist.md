# 主控审查清单

先跑 `review_diff.py <改动目录> --scope <任务范围>`，再按下面逐条只读相关的行。

## 必查
1. **范围**：有没有越界文件？有没有别的会话的改动混进来（`scope.py end` 的清单对一下）？
2. **内容对齐**：重写/翻新时，旧版本显示的每段文案都还在吗？对照的是**最初**版本，不是上一轮的中间版本。新增了原来没有的文案吗？
3. **失败分支对齐**：重写/改版时逐个请求对照旧实现的错误分支——原来静默或只轻提示的不要乱加重试弹窗；重试回调必须重做同一请求，不要调错函数；同一分支不要同时弹弹窗和 Toast 双提示。
4. **状态**：加载态（骨架形状和真实布局一致，而不是一个转圈）、空态、错误态 + 重试、下拉刷新不应重新出骨架。
5. **新文件**：加进版本库了吗？加进构建目标了吗？
6. **任务书要点**：逐条对照，编码角色报告的「差异」是否合理。

## 看逻辑时
- 删掉的代码：调用方还在吗？（用引用查找脚本，不靠肉眼）
- 共享组件被改：哪些其他页面会受影响？汇报时点名让用户去看。
- 设备与极端数据：安全区、横竖屏、深浅色（若项目支持）、长文本、空值与分页边界；列表/详情/表单改写验收前按 `references/ui-stress-test.md` 做最坏数据压测。

## 动态逻辑自检（喊用户编译前）
单张截图和静态 diff 检查覆盖不到动态行为。改动涉及以下纯逻辑时，先让编码角色用轻量单测或命令行验证脚本跑通，再喊用户进 IDE 编译验收：
- **数据解析与清洗**：空值/`<null>`、缺失字段、接口返回字符串布尔/数字（如 `"1"` / `"1,234.00"`）。
- **参数拼接与格式化**：无 `Optional(...)` 泄漏、金额精度与小数位、秒/毫秒时间戳转换。
- **边界与状态机**：0 / 1 / 满页 / 满页+1 分页边界、未知状态码兜底、失败重试状态复位。

单测留在正式测试目录；临时验证脚本只放 `$SOP_HOME` 或 `/tmp`，绝不留进业务代码。

## 审查反哺
- 审查发现的反复性错误，除了修代码，同步补进对应项目规则 / skill 或 `.agents/MEMORY.md`（写完跑 `scripts/memory_check.py`），防止下次再犯。
- 定期用 `scripts/memory_check.py --audit-rules` 清理过时规则，防止规则膨胀（见 `references/memory-and-handover.md`）。

## 汇报给用户
- 先结论（能不能验收），再列改动、差异、需要用户去看的页面。
- 发现范围外的问题：写进汇报，不顺手改。
