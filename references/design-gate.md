# 方向门

## 什么时候走
- 新页面、新视觉、大改版、用户说「优化设计 / 重新设计 / 让设计看看」：**走**。
- 只改少量细节的修订（颜色、间距、某个画板的文案或状态）：**不走**，直接出 revN。

## 流程
1. 主控写设计任务书：只写用户原话、事实（现有文案、接口字段、约束）和交付要求，**不写设计点子**。设计角色自己出方案、自己说理由。
2. 设计角色出 2–3 个方向。方向之间要有结构上的真实差异（布局、信息层级、交互方式），只换颜色不算。每个方向约 3 屏缩略稿 + 2–3 句「改了什么、优点、代价」。
3. 主控跑 `design_lint.py`，截一张能并排看到各方向的图，给用户看，**然后停下来等**。可以说设计方推荐哪个，但主控不替用户选。
4. 用户选定后，主控把原话写进 `direction-approved.md`（模板见 templates/）。之后的完整稿、修订都以它为准。
5. 完整稿交付后再跑一次 lint（带 `--base` 对比方向稿，带 `--source` 对比旧代码文案），error 为 0 才给用户看。

## 用户中途改主意
- 「改用方向一」：更新 direction-approved.md（追加一条，保留旧记录），出新一版完整稿；已经写好的代码只按新稿改受影响的部分。

## 反模板装饰（画板内禁止）
- 标题上方全大写英文小标签；中英双语混排标题
- 「A · B · C」中点串词当标题
- 按钮或链接末尾装饰性「→」
- 不是序列却用 01 / 02 / 03 编号
- 彩色渐变、emoji 当图标、卡片左侧彩色竖条、手画图标或人像
- 编造原页面没有的统计数字、评价、徽标墙
