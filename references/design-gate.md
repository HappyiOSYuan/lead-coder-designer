# 方向门

## 什么时候走
- 新页面、新视觉、大改版、用户说「优化设计 / 重新设计 / 让设计看看」：**走**。
- 只改少量细节的修订（颜色、间距、某个画板的文案或状态）：**不走**，直接出 revN。

## 流程
1. 主控写设计任务书：只写用户原话、事实（现有文案、接口字段、约束）和交付要求，**不写设计点子**。设计角色自己出方案、自己说理由。
2. 设计角色**先写设计思路**（`directions.md` 开头：重述需求、form 四问、每个方向一张方向卡、过头检查，模板见 templates/），写完再画缩略稿。然后出 2–3 个方向。方向之间要有结构上的真实差异（布局、信息层级、交互方式），只换颜色不算。每个方向约 3 屏缩略稿 + 2–3 句「改了什么、优点、代价」。
3. 主控跑 `design_lint.py`，按 `references/design-review.md` 审核「设计思路」和第 0、1 维，截一张能并排看到各方向的图，连同差异说明给用户看，**然后停下来等**。可以说设计方推荐哪个，但主控不替用户选。
4. 用户选定后，主控把原话写进 `direction-approved.md`（模板见 templates/）。之后的完整稿、修订都以它为准。
5. 完整稿 / rev 交付后再跑一次 lint（带 `--base` 对比方向稿，带 `--source` 对比旧代码文案），error 为 0 后截一张图，按 `references/design-review.md` 做 6 维打分并输出结论；不达标直接打回 rev，达标再给用户定稿。

## 改版已有页面：保留骨架
- 用户说「优化 / 重新设计」一个**已经上线**的页面时，方向要建立在现有页面上：骨架（如左侧分类栏 + 右侧卡片）、信息顺序不变，只改间距、字号层级、颜色、圆角、分隔线、对齐、图片尺寸。几个方向的差别在「侧重点」，不在结构。
- 主控在设计任务书里列出现有页面的实现文件让设计角色读，并用一句事实写清每个关键页面现在的骨架，写明「保留骨架」。仍然出 2–3 个方向、仍然内容不增不减。
- 反例：把分栏列表改成分段控件 / 仪表盘 / 普通列表，用户回「改动太大了，要基于现有的优化」。
- 新页面、或用户明说「结构也可以改」时不受这条限制。

## 用户中途改主意
- 「改用方向一」：更新 direction-approved.md（追加一条，保留旧记录），出新一版完整稿；已经写好的代码只按新稿改受影响的部分。

## 反模板装饰（画板内禁止）
- 标题上方全大写英文小标签；中英双语混排标题
- 「A · B · C」中点串词当标题
- 按钮或链接末尾装饰性「→」
- 不是序列却用 01 / 02 / 03 编号
- 彩色渐变、emoji 当图标、卡片左侧彩色竖条、手画图标或人像
- 编造原页面没有的统计数字、评价、徽标墙
