# 省 token

1. **定位先于派发**：主控把文件和行号写进任务书。模糊任务会让编码角色在项目里到处读文件。
2. **大范围搜索交给脚本**：引用查找、调用点统计、未使用资源等，写或复用一个脚本，输出汇总（计数、路径:行号、截断），完整结果写文件。不要让模型逐个读文件。
3. **只点 1–3 条相关规则**，不把整套规则塞进任务书。
4. **小改动不编译**：由用户或主控统一编译；需要编译时用汇总脚本，只输出错误和新增警告。
5. **日志只读结尾**：执行角色的报告在最后，`tail` 就够。
6. **一张截图**：一次验收只截一张覆盖关键区域的图，必要时缩小。
7. **大文件只读相关行段**。
8. **一个需求一个会话**：做完一个需求，下一个无关需求开新会话。
9. **设计任务控制交付物数量**：每多一个变体、一块说明面板、一台手机，都是成千上万 token。
