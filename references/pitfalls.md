# 踩过的坑（派发前过一眼）

| 坑 | 现象 | 做法 |
|---|---|---|
| 脱离启动执行角色 | `( cmd & )` / nohup 启动后终端看不到、完成没通知，只能手动轮询 | 用主控代理自带的后台任务功能运行 `run_role.sh` |
| CLI 等 stdin | 后台运行时卡在 "Reading additional input from stdin" 一整夜 | 一律 `< /dev/null`（run_role.sh 已处理） |
| 无头设计角色不能跑命令 | 设计角色花半小时爬资源目录、导出图标失败 | 主控提前把图标、截图、旧文案导出到设计目录，任务书写明「不运行命令」 |
| 额度用完 | 执行角色几秒就退出，日志里一句 quota | 配好备用模型；run_role.sh 识别到短日志 + 额度报错就自动换 |
| CLI 记住 --model | 一次指定模型后，以后都默认用它 | 适配器跑完还原配置（cursor-agent 适配器已处理） |
| 并发会话混改动 | 提交时混进别人的文件 | 每个任务 `scope.py start/end`，验收前核对清单 |
| 两个编码任务同时跑 | 互相覆盖文件、编译互相打断 | 串行排队：`a && b` 放进同一个后台任务 |
| 重写丢内容 | 新页面少了一句提示、一个按钮 | 对照**最初**版本的文案逐条核对；`design_lint.py --source` 自动查 |
| 设计稿加戏 | 多出原页面没有的徽标、相对时间、统计 | 任务书写死「内容不增不减」，lint `--base` 查新增文本 |
| 骨架和真实布局不一致 | 加载时出现基类通用骨架，数据回来后跳成卡片 | 关掉通用骨架，用和真实布局同形状的骨架；验收时专门看加载态 |
| 安全区被吃掉 | 底部按钮压在 Home 指示条上 | 查宿主是否清空了 safe area，从根上把 inset 传进来，不硬编码 34 |
| 共享组件改动波及 | 改一个页面的样式，另外 6 个页面也变了 | 审查时列出共享组件的所有使用方，汇报里点名让用户去看 |
| 主控替设计出点子 | 设计稿变成主控的想法，设计角色只是画图 | 任务书只写用户原话和事实，方案由设计角色出 |
| 无头设计角色一调 shell 就整轮作废 | 日志只有一句「a tool required the "command" permission」，什么都没写出来 | 任务书**第一行**写「只用读文件 / 写文件 / 列目录工具，绝对不要调用任何 shell 命令（包括 ls、cat、find、grep）」；新目录主控提前建好；跑完先看日志是不是这一句 |
| 无头设计角色读目录外文件被拒 | 日志一句「a tool required the read_file permission」 | 把参考文件提前放进设计目录或用 `--add-dir` 加进来，任务书写「只读写当前目录里的文件」 |
| 任务书重名 | 写任务书时同名旧文件已存在、写入被拒，同一轮里并行发出的启动命令跑了旧任务书 | 任务书用描述性的唯一文件名；**写入成功后**下一步再启动执行角色，不要和写入放在同一批 |
| 改版把结构推翻 | 「优化」已有页面，方向稿却换了骨架，用户嫌改动太大 | 任务书里写清现有骨架 +「保留骨架」，见 design-gate.md |
| 重写漏失败分支 | 成功路径都对，但失败时多出弹窗+Toast 双提示，或点击重试调了另一个接口 | 按原实现逐请求核对失败分支，并在项目规则里加静态 lint 兜底 |
| 主控额度用完丢现场 | 换个工具重开会话，不知道刚才派了什么任务、哪些待验收 | 派任务和待确认随手追加进 `$SOP_HOME/leader-handoff.md`，用 `takeover_lead.sh` 接管（见 memory-and-handover.md） |
| 记忆越写越长或散落多处 | 同一条约定写了两三份、过期条目误导新会话 | 唯一来源 `.agents/MEMORY.md`（≤150 行、带 `[标签]`），收尾自动跑 `memory_check.py` |
| 后台 shell 里 `ls` 卡住 | 本机把 `ls` 设成 `eza` 等交互别名，后台任务里挂死 | 脚本和后台命令里显式用 `/bin/ls` 或 Python 列目录 |
| 无限打回越改越乱 | 同一个设计或 bug 连续打回 3–4 轮，上下文和代码越修越脏 | 设熔断线：同一阶段连续 2 轮不通过就停，重查根因、必要时回滚或升级问用户 |
| 同类 bug 一条路径一条路径补 | 同一模块的「返回 / 保存」问题一天派了 3 次，每次只修用户指出的那条路径，熔断也没触发（每轮看起来都是新任务） | 同类行为第二次出 bug 就算第 2 轮：先出状态表（页面 × 操作 → 保留 / 回滚 / 删除），用户确认后一次修全 |
| 小改动不编译，用户当编译器 | 编译错误到用户手上才暴露，多一轮来回 | 改了代码就增量编译一次（只编改动模块），失败不交给用户 |
