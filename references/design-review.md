# 设计稿审核打分表（主控用）

参考 huashu-design `critique-guide`，按多角色 SOP 裁剪。审核由主控执行，目的是在交给用户或进入开发前挡掉模板化、漏内容和硬伤，而不是替设计角色出点子。

## 什么时候审

- **方向稿（Round 1）**：只审 `directions.md` 的「设计思路」和下表第 **0、1 维**，帮用户看清各方向的真实差别。**不替用户推荐或替选方向**，交由用户拍板。
- **完整稿 / 修订稿（rev）**：先跑 `scripts/design_lint.py`（error 必须为 0），再截一张覆盖关键画板的图，按下表逐维打分。

## 打分（每维 1–10）

| # | 维度 | 看什么 | 权重 |
|---|---|---|---|
| 0 | 立意 | `directions.md` 里的「form 来自内容的哪里」是否成立；把页面标题换成别的业务模块，这个设计还照样成立吗？成立就是套模板，本维最多 5 分 | **一票否决**：≤5 时总分封顶 6 |
| 1 | 平台一致性 | 遵循目标平台的设计规范（如 Apple HIG / Material / 项目既定设计系统）、字体与字号层级、语义色、边距与最小点击区、系统导航栏与材质边界 | ×1 |
| 2 | 视觉层级 | 眯眼看能不能分出 3–4 层；用户最常做的那件事是不是第一眼看到的；标题和正文的字号、字重拉开没有 | **×2** |
| 3 | 细节执行 | 间距是否统一按基准网格（如 4/8pt）取值；同类元素是否一致；配色是否收敛在主题色 + 语义色 + 灰阶；对齐 | **×2** |
| 4 | 功能性 | 逐个元素问：删掉它，页面会变差吗？最坏数据下会不会截断、溢出、错位；点击区够不够大 | **×2** |
| 5 | 原创性 | 有没有反模板装饰；多个方向是不是只换了皮肤 | ×1（可用性优先） |

计算方式：`总分 = (d0 + d1 + 2×d2 + 2×d3 + 2×d4 + d5) / 9`。若 `d0 ≤ 5`，总分封顶 `6.0`。

分级：
- **8.0–10.0（优秀）**：可交付用户定稿 / 进入开发
- **6.0–7.9（良好）**：无致命问题可交付，或顺手修一轮 rev
- **4.0–5.9（需改）**：打回设计角色出 rev
- **< 4.0（不合格）**：打回重做

## 内容一致性（不打分，有一条就打回）

- 改版/重写出现文案缺失或新增（对照 `design_lint.py --base` / `--source` 逐条核对）
- 使用了约定图标集以外的图标，或手画图标
- 违反项目外观约束（例如只做浅色时出现暗色屏或暗色 token）

## 输出格式（发给用户）

```text
结论：总分 X.X（优秀 8+ / 良好 6–7.9 / 需改 4–5.9 / 不合格 <4），能不能进入下一步
依据：lint 结果 + 截图 + 6 维各一句
问题（按严重程度）：
  - ⚠️ 致命 / ⚡ 重要 / 💡 优化 —— 现状 → 违反了哪条规则或标准（附具体数值）
下一步：打回 rev / 交给用户确认 / 进入写代码
```

## 边界

- **只指问题，不出点子**：问题只写「现状是什么、违反了哪条标准、标准数值是多少」，**不写替代设计方案**；怎么改由设计角色决定。
- **用户裁定优先**：主控打分与用户的选择冲突时，以用户为准；用户对设计好坏的原话记进 `direction-approved.md`。
