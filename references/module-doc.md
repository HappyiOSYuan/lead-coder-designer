# 模块文档（模块完成后的 PRD 式总结）

一个模块整体做完、用户验收过之后，最后补一份总结，方便以后不读代码也能查：接口、业务逻辑、流程、已知问题。

## 什么时候写
- 只在**用户点名某个模块**时写；不要主动批量补写旧模块。
- 第一次在一个项目里用：先写一个模块当样例，用户确认格式后再写其他模块。

## 流程
1. **主控出骨架**：按 `templates/module-doc.md` 建 `<文档目录>/<模块>.md`（建议版本库忽略，如 `ModuleDocs/`）。能从代码里机械取到的部分（文件清单、接口路径表）主控用脚本填好，其余段落留 `TODO`。
2. **编码角色填写**：任务书写明「只改这一个 md 文件，不动代码」；内容只来自代码和本次任务记录，不编；看不出来的写「待确认」；每条业务规则注明 `文件:行号`。
3. **主控审核**：抽查业务规则里注明的行号、接口参数，确认 TODO 都填完。
4. （可选）生成查阅用网页：Markdown 始终是原稿，网页由脚本从 md 生成、不手改。
5. 以后这个模块再改动：在「变更记录」加一行，内容有变化的段落同步改掉，再重新生成网页。

## 写法约定
- 多层字段表前用 `####` 四级标题，不用加粗当小标题。
- 业务逻辑按 `### 子模块` → `#### 场景` 分组，每组 3–5 条。
- 流程图用 mermaid。
