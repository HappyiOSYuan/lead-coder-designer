# 项目记忆、历史检索与主控交接

长期跑多轮需求时，最容易丢三样东西：**反复踩过的坑**、**用户以前拍板过的口径**、**主控额度用完换人时的现场**。用下面三件轻工具把它们固定下来。

---

## 1. 单一项目记忆（`.agents/MEMORY.md`）

- **唯一来源**：所有跨会话成立的项目事实、流程约定、避坑经验，统一只写项目根的 `.agents/MEMORY.md`，不要散落在聊天历史或多个私有目录里。
- **格式**：一条一行，开头写 `[标签/标签]`（供任务书按标签检索），陈述事实而不写死板祈使句；通用代码规范写进项目规则文件，这里只留一句「见 xx」。
- **硬上限**：严格控制在 **150 行以内**。新增前先合并同类项、覆盖过时结论、删已失效条目，禁止只增不减。
- **收尾复盘闭环**：每次任务结束必须回答「这次有没有踩坑、被用户纠偏、或定下新约定？」——有则写回 `.agents/MEMORY.md`（执行角色写在报告「复盘」栏，由主控审核写入），无则显式写「复盘：无」。
- **自动体检**：改完跑 `scripts/memory_check.py`（检查行数、缺失 `[标签]`、同标签近重复、失效的仓库路径）；`scripts/review_diff.py` 也会在收尾自动检查。
- **自动注入任务书**：主控写任务书前跑 `python3 -I scripts/memory_check.py --match "<需求关键词或模块名>"`，把命中的相关条目抄进任务书的「相关记忆」小节；执行角色不用自己通读整份记忆。

示例条目：

```markdown
- [流程/提交] 所有代理不执行 commit，收尾只列改动文件和分支/changelist。
- [Swift/参数] 拼接口参数禁止把 Optional 强转 `as Any` 后插值，会变成 `Optional("0")`（2026-11-19）。
```

## 2. 历史会话原话检索（`scripts/session_search.py`）

记不清用户某条规则当初怎么拍板时，不要猜，直接无 LLM 搜本地会话日志（目前支持 Claude Code 的 `~/.claude/projects/*/*.jsonl`）：

```bash
python3 -I scripts/session_search.py 关键词 --role user        # 只看用户原话
python3 -I scripts/session_search.py --session <sid> --around 12  # 查看命中上下文
```

默认按当前工作区目录名过滤项目，加 `--all-projects` 可跨项目检索。

---

## 3. 主控热接管与交接协议（`leader-handoff.md`）

主控和执行角色一样，也可能遇到额度耗尽或需要临时切模型。与其重开空会话重讲一遍上下文，不如按交接文件平滑接管：

1. **共用交接文件**：默认放在 `$SOP_HOME/leader-handoff.md`（工程目录外）。
2. **随时追加记录**：无论原主控还是接管主控，每完成一件事、派出一个后台任务或留下待用户确认事项，就在文件末尾追加一行：
   ```markdown
   - 2026-11-21 15:20 [Lead-A] 派发编码任务 `brief-login-fix.md`（预计 3 分钟），待审 diff
   - 2026-11-21 15:45 [Lead-B] 审完 diff（review_diff error 0），待用户编译打开登录页验收
   ```
3. **一键接管**：在 `.sop/config.sh` 配好 `LEAD_BACKUP_CMD` 后，运行：
   ```bash
   scripts/takeover_lead.sh          # 启动备选主控并自动读 AGENTS.md + MEMORY.md + leader-handoff.md
   scripts/takeover_lead.sh -c       # 继续上一次接管会话
   ```
4. **原主控恢复**：先跑 `python3 -I scripts/handoff_rotate.py`（只留最近 7 天，旧记录归档到同目录 `leader-handoff-archive.md`；`takeover_lead.sh` 启动时自动跑），再读 `leader-handoff.md` 末尾新增的记录继续，避免重复派发或漏掉待确认项。
5. **验收行**：每个任务验收时补一行，供以后按数据删关卡（见 `SKILL.md` 第 6 节）：
   ```markdown
   - 2026-11-24 [Lead-A] 登录页修复 · 验收 · 轮次 2 · 发现者 编译/用户
   ```
   轮次 = 派了几次才通过；发现者 = 每轮问题最后由谁发现（脚本 / 审diff / 编译 / 用户）。用户说「好了 / 可以 / 提交了」或开始下一个任务时就补，拿不准写「?」。
6. **交接底线**：接管主控严格遵守同一套 `AGENTS.md` 分工边界——同样不直接改业务代码、不提交版本库。

## 4. 规则与技能的定期清理（防熵增）

规则、技能和脚本同样是代码，会随架构演进而腐化；只增不减会稀释注意力、拖慢检索并引发误报。

- **触发时机**：每完成一个里程碑（如一个模块交付、旧框架/旧语言迁移收尾）跑一次审计：
  ```bash
  python3 -I scripts/memory_check.py --audit-rules .cursor/rules .cursor/skills --stale-days 90
  ```
- **重点清理 3 类过时资产**：
  1. **已退出架构的规则**：旧语言/旧库已彻底下线后，及时归档或删除对应规则和辅助脚本。
  2. **已被静态 lint 接管的规则**：能用 `review_diff.py --rules` 机械拦截的条目，不要在文字规则里重复写大段说明，缩成一句索引。
  3. **失效路径与过长文件**：引用的类/文件已删除、或单篇超过 300 行的规则文件，按需裁剪或合并。
- **AGENTS.md 设上限**（如 140 行）：它每个代理每次都读，成本按次累加；超了就把细节挪进对应 skill / 规则，AGENTS.md 只留索引。
- **关卡也要清理**：按交接文件里的验收行统计，长期从不拦截问题的检查脚本或审查步骤，交用户确认后删掉；攒够数据前不新增流程规则。
- **执行底线**：清理清单由主控整理后交用户确认，确认后再删，不私自大面积删除规则。
